# Mind Garden 운영 가이드

최종 업데이트: 2026-09-27

## 1. 제품 운영 원칙
- Mind Garden의 핵심 루프는 **햇살 휴식 → 꽃 성장 → 개화 → 포인트 획득 → 새 씨앗 구매 → 내 정원 확장**이다.
- 휴식 중에는 화면을 켠 상태로 유지한다.
- 앱/탭을 벗어나면 햇살 휴식은 즉시 정지하고 자동 재개하지 않는다.
- 사용자가 실패했다고 느끼는 벌점/시들음/초기화는 기본적으로 사용하지 않는다.
- 실제 생육 단계와 외형은 최대한 현실적으로 표현하되, 성장 시간은 습관 형성용으로 압축한다.

## 2. 꽃 성장 단계 표준
모든 꽃은 아래 6단계를 기본으로 사용한다.
1. seed — 씨앗
2. germination — 발아
3. sprout — 새싹
4. true_leaves — 본잎
5. bud — 봉오리
6. bloom — 개화

꽃 종류별로 각 단계의 실제 외형 이미지를 따로 관리한다.

## 3. 현재 9월 꽃 카탈로그
| 꽃 | 씨앗 가격 | 난이도 | 앱 성장시간 | 기본 완성 보상 |
|---|---:|---|---:|---:|
| 금잔화 (Calendula) | 40P | 쉬움 | 90분 | 120P |
| 수레국화 (Cornflower) | 60P | 보통 | 120분 | 150P |
| 팬지 (Pansy) | 80P | 보통+ | 150분 | 180P |
| 니겔라 (Nigella) | 100P | 어려움 | 180분 | 220P |

신규 사용자는 시작용 금잔화 씨앗 1개를 무료 지급한다.

## 4. 포인트 정책
- 꽃을 완성하면 꽃별 기본 보상을 지급한다.
- 하루 첫 완성은 +20P 보너스를 지급한다.
- 포인트는 씨앗, 화분, 배경 해금에 사용한다.
- 포인트는 현금성 가치로 운영하지 않는다.

## 5. 관리 행동 정책
기본 성장 뼈대는 동일하되 물주기/잎 닦기 기록은 향후 관리점수에 반영한다.
- 물주기: 일 1회 유효
- 잎 닦기: 일 1회 유효
- 권장: 관리점수 0~100
- 관리점수는 성장 효율과 최종 개화 외형(잎 풍성함, 봉오리 수, 색감)에 소폭 반영한다.
- 관리 부족으로 꽃이 죽거나 모든 진행이 초기화되지는 않도록 한다.

## 6. 성장 이미지 운영 규칙
- 이미지 포맷: WebP 권장
- 권장 크기: 768×768 또는 그 이하
- 파일 경로 규칙: `growth/{species_key}/{stage_key}.webp`
- 예: `growth/calendula/bloom.webp`
- 동일 종/동일 단계의 기본 이미지는 공통 사용한다.
- 추후 관리점수나 랜덤 변형이 필요하면 `variant_key`를 추가한다.
- 새 이미지 교체 시 기존 오브젝트를 덮어쓰기보다 `asset_version`을 올리고 D1 메타데이터를 갱신한다.

## 7. Cloudflare 저장 구조
### D1
정형 데이터 저장:
- 꽃 종류
- 난이도/가격/성장시간/보상
- 성장 단계
- R2 object key
- image URL
- asset version
- 활성/비활성 상태

### R2
실제 이미지 바이너리 저장:
- `growth/calendula/seed.webp`
- `growth/calendula/germination.webp`
- `growth/calendula/sprout.webp`
- `growth/calendula/true_leaves.webp`
- `growth/calendula/bud.webp`
- `growth/calendula/bloom.webp`

이미지 바이너리를 D1 BLOB로 직접 넣지 않는다. R2에 보관하고 D1이 위치를 가리키는 방식으로 운영한다.

## 8. 공개 정원 확장 원칙
- 완성 꽃은 기본 `private`
- 사용자가 명시적으로 선택한 꽃만 공개
- 실제 집 사진은 기본 비공개
- 공개 정원에서는 가상 배경/렌더링된 정원 장면을 우선 사용
- 공개용 데이터는 최소화: 닉네임, 꽃, 완성일, 화분/배경, 선택적 통계

## 9. 이미지 검수 체크리스트
새 성장 이미지를 등록할 때 아래를 모두 확인한다.
- 실제 해당 꽃의 생장 단계와 유사한가
- 이전/다음 단계보다 성장 정도가 자연스러운가
- 동일 화분/배경 톤이 유지되는가
- 텍스트/워터마크/불필요한 물체가 없는가
- 모바일에서 식물이 작게 보이지 않는가
- R2 object key와 D1 stage key가 정확히 일치하는가

## 10. 변경 절차
1. 운영 가이드 수정
2. 카탈로그/DB schema 또는 seed 갱신
3. 성장 이미지 생성 및 검수
4. R2 업로드
5. D1 메타데이터 갱신
6. 웹에서 우선 검증
7. 사용자 확인 후 APK 빌드

웹 우선 원칙을 유지한다.
